# 执行与通知闭环

开工、修改代码、巡检及完成/取消时读取。本文约束 agent 使用现有 SSH、MCP 与宿主调度能力，不给 TrainOps CLI 新增训练执行器、通知服务或常驻调度器；原有计划、无卡准备、多机调度、五次自愈止付和实验日志流程不变。

TrainPilot 的通知、按钮决定与直接对话接管见[TrainPilot 通知与决定](trainpilot.md)，按需读取；新任务由用户直接交办。

先按[入口](../SKILL.md#开工与接管)明确用户选择 AutoDL 实例或在 Vast.ai 寻找。下文 AutoDL 状态查询、UUID、开机/切换 job、`cancel_job` 与 `/etc/network_turbo` 仅适用于 AutoDL；Vast.ai 必须加载外部 `vastai:vastai` skill，按 [Vast.ai 参考](vastai.md) 核实实例 ID、SSH 映射、状态与资源操作，不执行 AutoDL 专用初始化。通用通知、代码同步、训练核实和宿主调度清理适用于两者；Vast.ai 收尾核对实例及实际等待/复制任务，stop 与 destroy 的授权分开。

## 即时状态通知

三条通道职责独立，不能相互顶替：

**`lark-cli` 写多维表格是被动档案留痕，TrainPilot 发卡片是主动即时通知；两者的飞书凭据与调用逻辑独立。`synced to Feishu` 只说明写表成功，绝不代表已发送即时汇报。** 每次巡检依次执行计划/Run 更新和 TrainPilot 通知，写表失败仍继续通知。

- **MCP `trainpilot`**：主动推送任务状态，让用户不在屏幕前也能即时获取训练状况。
- **`lark-cli` 实验日志**：记录 Run、配置变化、真实指标和证据，用于对照与迭代分析；仍按[实验日志](experiments.md)先读后写。
- **任务面板与当前对话**：展示计划、进度和操作回执。更新面板、写表成功或对话回复均不等于已发送 `trainpilot` 通知。

1. **开工检查**：实际调用 AutoDL 状态查询核对已授权实例，实例可连接时通过 SSH 执行只读检查；新训练启动前必须按 [TrainPilot 开工探针](trainpilot.md#调用与开工探针)实际调用 `get_task_status` 或发送真实开工 `report`，判读返回后才放行。工具名与参数以当前实际工具说明为准，不猜完整限定名。缺工具、授权、连接或探针未通过时说明实际阻塞与影响，解决通知阻塞或取得用户明确同意的替代通知方案后再启动新训练，不声称操作或通知成功。通知不可用不静默改用实验日志冒充推送；接管已有训练先核实现状，不因探针失败中断进程，不阻断安全处置或关机止付。
2. **固定巡检**：训练进入 running 后，按[入口](../SKILL.md#唤醒与汇报)与[宿主能力适配](hosts.md#定时巡检与资源等待)实际创建整点/半点宿主调度任务；记录宿主任务标识、覆盖的训练任务/实例、用途、关联 AutoDL `job_id` 及取消入口，区分宿主 tasks ID、AutoDL `job_id` 与 TrainPilot `task_id`。每个巡检/汇报/资源等待 Prompt 都先检查任务是否已结束或收到结束/取消指令，若是则收尾并取消自身，不再申请资源、启动训练或续建调度。资源等待的一次性唤醒也记录对应 `job_id`。不得只承诺定时检查；工具不可用或会话生命周期不足以持续调度时，说明限制并与用户确认可用方案，不得声称已建立持续监控。新会话先核实已有调度，不重复创建。
3. **每次巡检**：通过 SSH 和 AutoDL 真实检查实例状态、训练进程、GPU 使用情况、日志是否持续更新、训练进度、可获取的关键指标、异常和下一步动作。无法获取的项明确标为未知，不编造指标；仅进程存活不能证明训练正常推进。按顺序更新真实计划进度、`experiment update` 留痕、实际调用 TrainPilot `report` 并核实返回、最后在当前对话总结；Lazy MCP 的调用结构见 [TrainPilot](trainpilot.md#调用与开工探针)。正常巡检用 milestone，终态和修复遵守下述单次汇报规则；不能只写 `--checked` 或输出调用代码块而不执行。
4. **重大节点立即额外通知**：开机成功、代码同步完成、训练启动、阶段完成、评估完成、训练失败或异常中断、恢复运行、任务完成及关机完成，不等下一次固定巡检。说明对应任务/实例、真实结果及下一步；失败通知附已核实证据。通知只含脱敏摘要和必要引用，不发送凭据或完整敏感日志。
5. **发送结果核实**：依据实际工具返回区分事件记录与通知送达，`report(success=true)` 不等于飞书已送达。终态直接 report completed/failed；修复验证后用 ACK 合并汇报，不重复发恢复 milestone。失败如实报告并后续补报，不密集重试、不算作训练自愈次数，不为通知延迟必要的止付和产物保护。实验日志同步失败也不能阻断即时通知。

## 本地代码同步

需要修改具体代码时执行以下顺序；无代码变更时核对已有版本即可，不创建空提交或无故推送。

1. **核实目标与工作区**：确认本地和服务器对应的仓库、分支、提交版本及未提交修改；保留用户已有工作，不夹带无关改动。实例 UUID 与 SSH 别名必须来自用户明确提供或项目已有且已核实的映射，缺失或有歧义先询问，不猜测其他机器；连接信息变化后先核对实际 SSH 目标。
2. **本地修改与验证**：在本项目本地工作区修改代码和配置，完成适用检查，保留修改记录。资源不足的验证按无卡/有卡阶段分配，不虚报已通过。**不在服务器直接修改受版本管理的代码**，无卡准备中的代码调整也遵守此规则。
3. **提交并推送**：只提交任务相关变更，记录实际 commit，再推送到对应远程分支；具体任务已授权本链路的提交推送才执行，否则先取得授权，不把仅加载插件当成授权。不覆盖用户未提交工作、不强制推送；遇到冲突或权限问题先核实并报告，不跳过同步直接训练。
4. **远端拉取并核对**：服务器对应仓库拉取已推送版本，再核实仓库、分支与 commit 一致，且没有未说明的工作区差异；有冲突不强制覆盖。每次远程执行准备/训练脚本前，在远端 Bash 执行 `source /etc/network_turbo`，不是本机初始化命令。核对通过才执行，并立即通知代码同步完成。
5. **可恢复启动**：用 tmux/screen 等 SSH 断开后继续运行的方式启动；先排除重复进程。在远端本项目可定位的启动记录中保存会话或进程标识、日志路径、输出目录、实际启动命令与 commit，敏感参数脱敏；在 Run 的 `config_path` / `artifacts` 中留必要引用，不向 `plan` 塞命令和日志。已有未提交变更的接管记录可保留配置快照与 patch 证据，但不是允许绕过上述同步流程的新修改入口。

## 完成或取消收尾

任务完成或用户取消后必须执行最终闭环。用户直接告知“任务结束了”“不用继续”“停止/取消”时也立即触发，不等下一次巡检；失败且不再继续执行时同样收尾。结束本任务已授权取消其不再需要的后台调度和资源请求，无需另问是否取消 tasks；实例关机仍按下述授权边界执行。部分任务结束时仅收尾对应范围，不影响其他仍在运行或等待的任务。

**先停止新增调度和资源请求，再执行清理，最后汇报**。TrainPilot 的 completed/failed/取消回执、计划终态、结束对话均不会自动取消宿主 tasks 或 AutoDL 后台 job；不能发完终态通知就结束本轮。接管或历史记录缺失时，先通过宿主实际提供的任务列表/查询工具核对本项目相关调度，再结合已记录的 AutoDL `job_id` 查询；不能因为当前上下文没有 ID 就断言没有残留，也不猜测不存在的工具名。

1. **核实进程与产物**：完成时确认训练及相关子进程退出、结果与 checkpoint 已保存；取消时按授权结束本任务进程并保留必要产物，结果未知先核实，不虚标 done。失败保存诊断信息，故障恢复与止付仍按[协议](protocol.md)执行。
2. **更新计划与实验日志**：按真实结果登记 done / cancelled / failed / blocked，先读 Run 再 update / sync，保留证据；飞书失败保留本地 pending 并报告，不阻断后续资源清理。
3. **清理本任务调度与等待**：核对创建时记录的任务标识，实际调用宿主取消/删除工具清理定时巡检、资源等待唤醒，以及定时汇报、重试、延迟启动和本任务监控/轮询。当前唤醒若来自周期任务，也要取消该周期任务自身。另对本任务不再需要且仍活动的 AutoDL 开机/切换 `job_id` 实际调用 `cancel_job`，包括 `power_on` 缺货时的持续开机请求；仅取消宿主唤醒不会停止 MCP 后台重试。已终态的 job 核实记录即可，不必重复取消。取消宿主唤醒不等于取消 AutoDL job，`cancel_job` 也不等于关机，须判读其返回物理状态，过渡态或查询失败再核实。共享巡检仍覆盖其他活动任务时保留并更新范围，共用资源请求先核实归属，不清理其他任务的调度。取消后用宿主列表/查询复查调度已删除或停用，用 `job_status` 或取消回执核实 AutoDL job 已终止；对已经触发的回调核实其未继续开机或重建调度。工具不可用、ID 无法找回或取消失败时明确列出残留、影响和下一步，不声称全部完成。
4. **实例最终状态**：按已有授权、其他训练和后续复用情况处置实例；满足最终关机条件时及时关机并核实物理终态。不得关闭仍有其他任务运行的实例；用户选择“取消任务并关机”时已授权对应专属实例关机，执行后核实。不包含关机授权的取消则按已有约定处理，无授权时明确报告实例仍在运行及待确认事项。关机规则与五次自愈止付预授权保持不变，见[恢复与关机](protocol.md#恢复与关机)。
5. **最终汇报**：通过 MCP `trainpilot` 和当前对话汇报任务最终结果、结果/checkpoint/诊断信息的真实位置、实例最终状态（仍在运行则说明原因）、调度与等待清理结果（宿主任务 ID、AutoDL `job_id`、取消/已终态/共享保留/失败及核实依据），以及未完成事项和所需决策。通知失败按上节处理，不能把对话回复当作推送成功。

**任务面板可以保留**：不把完成/取消收尾解释为必须停止 `serve`，也不强制清空计划、删除 Run 或关闭其他任务的巡检；面板继续按原有生命周期运行。
