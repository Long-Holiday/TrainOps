# AutoDL 配置

仅选择开机模式、配置存储、TensorBoard、余额结算或面板时读取；异常恢复见 [协议](protocol.md)。设 `CLI="python3 <技能目录>/scripts/trainops.py -p <实验项目目录>"`。

## 无卡准备与训练开机

目标是把项目理解、环境配置与代码调整前置到无卡阶段，减少正式开机后 GPU 空等；不是省略 GPU 验证，也不承诺无卡免费。

无卡模式开机使用的是**本次开机 0.5 核 CPU、2GB 内存、无 GPU** 的配置，不是原实例 CPU/内存规格不变而仅取消 GPU。无卡准备只安排适配该资源的轻量工作：阅读/修改代码与配置、检查路径、语法及少量数据读取；安装、编译和数据加载须限制并发与内存占用。重型编译、全量数据预处理、大模型加载等超出资源的工作，安排到授权且资源充足的环境，或留到有卡阶段补验，并同步待办，不阻塞其他可推进实验。因该资源上限无法完成的检查不等于环境损坏，不反复重试到 OOM，也不擅自升级付费资源。

开关机由外部 `autodl_mcp` 执行，TrainOps 仅记账。已核对本机实现：适用于普通 AutoDL 容器实例，不适用于 Pro；无卡开机仍会计费，仅支持 `charge_type="payg"` 的按量实例。开关机、持续请求及其费用须在用户授权范围内；仅启用本技能不构成授权。调用前核实当前 MCP 工具说明；若版本不支持无卡模式或实例不满足条件，说明限制并确认替代方案，不静默改成付费 GPU 开机。

| MCP 工具 | 参数 | 结果与边界 |
|---|---|---|
| `instance_status` | `instance_uuid` | 只读查询 `status`、`start_mode`、`charge_type` 及 `gpu_name`、`gpu_memory_gb`、`cpu_cores`；关机也可查规格，无需 SSH；无卡运行模式为 `non_gpu` |
| `list_instances` | `instance_uuids=[...]` | 只读批量查询 1–100 个完整 UUID，支持去重、白名单校验和逐项错误；共享一次分页遍历，硬件查询最多 5 路并发 |
| `switch_mode` | `instance_uuid`, `target_mode="gpu"` 或 `"non_gpu"` | 返回 `job_id`；单个后台任务完成关机、确认关机、目标模式开机并复用缺货重试；须确认中断与计费影响，不是可回滚事务 |
| `power_on_no_gpu` | `instance_uuid` | 无卡开机，立即返回 `job_id`，任务中 `no_gpu=true`；不会自动把已运行的有卡实例切成无卡 |
| `power_on` | `instance_uuid` | 有卡开机，立即返回 `job_id`；缺货时后台持续重试，没有另一个“持续开机”工具，也没有每次调用的等待模式参数 |
| `job_status` | `job_id` | 只读即时查询开机/切换任务的 `phase`、`elapsed_seconds`、`attempts`、`next_retry_at`、`error`，不是查询训练进度 |
| `wait_for_job` | `job_id`, `timeout_seconds=15`, `return_on_capacity=True` | 只读等待，终态或 `waiting_capacity` 默认立即返回，指定 120 秒也不硬等缺货；显式 `return_on_capacity=False` 才继续等缺货；超时返回快照；时长支持 0–300 秒，0 为立即查询 |
| `cancel_job` | `job_id` | 只取消后续尝试，不撤销已接受的开机请求，不自动关机 |
| `power_off` | `instance_uuid` | 先取消活动开机/切换任务，防止后续自动拉起，再请求关机；返回接受结果，不代表关机已完成 |

`instance_uuid` 是平台完整 UUID，不是账本编号 `I01`；从已核实的实例映射取值。MCP 服务名前缀由接入环境决定，不猜完整限定工具名。MCP 使用控制台登录 Token，TrainOps 余额接口使用面板上登记的那份开发者 Token，两者分开配置，别互相顶替（登录 Token 填进面板也拉不到余额）。

**规格用于筛选，不是运行资源证明**：`gpu_name`、`gpu_memory_gb`、`cpu_cores` 来自控制台“规格详情”的配置快照；显存是单卡容量，按 1024³ 字节换算，不能当作多卡总量或当前空闲显存；CPU 是实例分配的 vCPU 数。缺失或无效的可选字段为 `null`，保留待核实，不补 0、不猜型号。可在关机时比较候选实例与实验需求，不为查规格开机或 SSH；无卡阶段仍以 0.5 核 CPU、2GB 内存、无 GPU 为准，不能套用快照规格。实际 GPU 就绪仍须运行态验证。

**等待只观察，不控制任务**：优先 `wait_for_job(job_id, timeout_seconds=15)`，即时看进度用 `job_status`。默认进入 `waiting_capacity` 即返回，不受更长 `timeout_seconds` 影响；及时汇报 `phase`、`elapsed_seconds`、`attempts`、`next_retry_at`，优先推进其他合格实例或准备工作。`elapsed_seconds` 是后台任务耗时，不是训练进度或预计有货时间。确需继续等待且在授权范围内时用 `wait_for_job(job_id, timeout_seconds=15, return_on_capacity=False)`，不在缺货返回后紧密重复默认调用。单次等待时长不超过用户剩余授权等待范围与调用方工具超时上限（必要时缩短 `timeout_seconds`）；返回后按 `phase` 判断，不把等待超时当作开机失败或成功。等待超时、连接断开或取消等待请求均不会取消后台开机任务，需停止后续尝试时另按授权 `cancel_job`。长轮询不增加上游轮询或开机请求；后台开机重试只查询运行状态，不额外查规格，调用方也不为等结果反复查硬件或重发开机。当前 MCP 未提供该工具时才用 `job_status` 按合理间隔查询，避免密集轮询。

1. **接管并核实**：先 `show --brief`，多实例优先 `list_instances(instance_uuids=[...])`，每批 1–100 个完整 UUID，按实验需求筛选候选；单实例、批量工具不可用或操作后定点复核用 `instance_status(instance_uuid)` 核实目标实例、开机模式、计费类型与硬件规格。逐项检查结果，失败项保留待核实，不当作实例不存在，不立即重查整批，也不在调用方另编排硬件并发；运行实例再 SSH 检查已有进程。已有训练运行时直接接管巡检，不为无卡准备而打断；已有 GPU 开机且是否可关机不明时先确认，不擅自重启。
2. **无卡准备**：需要远端准备时默认调用 `power_on_no_gpu(instance_uuid)`，保留返回的 `job_id` 并用 `wait_for_job(job_id, timeout_seconds=15)` 等待，按返回 `phase` 确认成功；用 `instance_status` 确认 `status="running"` 且 `start_mode="non_gpu"`。SSH 可达后了解项目结构、训练入口、数据与已有产物，检查环境/依赖、磁盘和路径；执行准备脚本前 `source /etc/network_turbo`，完成配置、代码调整及无需 GPU 的导入、语法、数据读取等检查。无卡阶段不启动 GPU 训练，不把待训练任务标为 running，也不因没有 GPU 就认定环境损坏。
3. **准备就绪后切换**：确认配置与代码已落盘、下载/安装等准备进程已结束、必要产物已保存；确认本次中断与计费影响已获授权后，已运行的无卡实例优先 `switch_mode(instance_uuid, target_mode="gpu")`，反向切换用 `target_mode="non_gpu"`。已有授权明确覆盖本次操作则不重复询问，否则先确认；已有训练不为准备而打断。切换不是热切换或可回滚事务，由后台任务确认关机后才开机；保留 `job_id`，按上述等待策略观察。切换活动期间不并行提交同实例的开机或另一切换请求；失败可能已关机，先查真实状态，不盲目重试。工具不支持时才按授权 `power_off` → `instance_status` 确认关机 → `power_on`；`accepted=true` 或 `shutting_down` 均不够，认可的已停止状态是 `shutdown`、`shutdown_by_starting_error`、`shutdown_by_running_error`，遇错误关机先核实原因。这是保留实例与后续训练计划的中间关机，不是释放实例，也不要求“所有流程无后续复用”。尚未准备完成不得提前申请 GPU。
4. **观察训练开机**：上一步已提交切换任务时复用该 `job_id`，不再调用 `power_on`；已关机实例或分步切换确认关机后调用 `power_on(instance_uuid)`；有资源时开机，缺货自动进入后台等待，持续请求不是另一种工具。保留 `job_id`，优先用 `wait_for_job` 等待，需即时进度时用 `job_status`；按返回 `phase` 判断：`waiting_capacity` 表示缺货等待，`waiting_network` 表示网络/限流退避，`queued/checking/starting/confirming` 都不是最终成功，`succeeded` 才是任务确认成功，`failed/cancelled` 须处置。请求已提交不等于开机成功，不循环重发 `power_on`，也不伪造训练进度。超出用户约定等待范围时按授权 `cancel_job`，随后查 `instance_status`，不能假定取消后实例已关机；失败且 `error.ambiguous=true` 时先查询实例，不盲目重试。
5. **GPU 就绪再训练**：用 `instance_status` 确认 `status="running"` 且不是 `start_mode="non_gpu"`，再检查 SSH、`nvidia-smi` 及训练框架能否使用预期 GPU；`start_mode` 缺失不能单独作为有卡证据。复核挂载、环境与训练入口，无卡阶段无法验证的 GPU 相关项在此补验。确认依赖满足后，用 tmux/screen 启动正式训练并登记真实状态与进度；若 GPU 验证失败，不启动训练，及时处置，避免付费空转：自愈最多 5 次，仍无法继续即先关机止付，见 [协议](protocol.md#故障自愈与止付关机)。

后台等待由 MCP 进程承担：`AUTODL_MAX_WAIT_SECONDS` 默认 0（不限缺货等待时间），不是 `power_on` 的参数；需要有限等待时与用户约定服务配置或取消时点。后台任务仅保存在当前 MCP 进程中，服务退出会取消任务但不会自动关机，重启后旧 `job_id` 无法恢复；接管先查实例真实状态，不因任务不存在就重发开机。不同模式的活动任务冲突时先按授权取消并核实实例；已运行的不同模式必须先关机，不会原地切换；优先由已授权的 `switch_mode` 完成，不另手工插入开关机。止付仍用 `power_off`，不能用切成无卡代替关机。

**账本与费用边界**：MCP 当前没有可信的准确报价，`price: null` 及其原因表示价格未知，不代表免费；不覆盖面板已有费率，不补零，也不据此作成本最优结论。实例状态只表示电源/可达性，不区分无卡与有卡；无卡已开机仍登记 `on`，不能用 `off` 冒充“不占 GPU”。持续请求期间按真实电源状态记录，不能仅因请求已提交就标为 `on`。开机模式另用 `--mode` 记录：无卡准备与持续请求等待期间是 `--mode no-gpu`，正式有卡开机是 `--mode gpu`，核实不了就 `--mode none`（未观测）而不是猜。两种模式各有自己的费率——无卡按 `no_gpu_price`（平台默认 0.1 元/小时，无卡不等于免费），有卡按 `price`（GPU 时价）——两者互不覆盖，由用户在面板（`serve`）的实例卡上登记。切模式后等面板下一轮结算（或在面板上重新登记一次 Token 触发立即结算），免得沿用旧口径；不填 0、不拿一个档位的价格冒充另一个档位。模式未登记时按 GPU 时价算，宁可高估花费。磁盘等费用以平台实际计费为准。

## 三盘与用量

| 路径 | 保留边界 | 内容 |
|---|---|---|
| `/` 系统盘 | 关机保留，随镜像保存；容量小且与系统共用 | 代码、conda 环境、配置脚本 |
| `/root/autodl-tmp` 数据盘 | 快；关机保留，不随镜像保存，释放实例即丢 | 数据集、checkpoint、TensorBoard 事件、高 IO 临时产物 |
| `/root/autodl-fs` 文件存储 | **同一账号下所有实例共享同一份**，不受开关机/保存镜像影响 | 最终权重、评测结果、需共享或长期保留的数据 |

**`/root/autodl-fs` 对所有实例是共享的**：同一账号下的每个实例挂载的是同一份文件存储，任一台写入，其余实例立刻可见——不用在实例间互传或 scp。据此安排两件事：跨实例交接直接落在它上面（只需上传一次的数据集、对照实验共用的输入、需要汇总的评测结果），各实例按自己的编号建目录（如 `/root/autodl-fs/<项目名>/F01-T02/`），几台同时往同一路径写会真的撞在一起，覆盖或互相删除都发生在共享盘上；反过来，清理共享盘前先确认不是别的实例或别的实验正在用的产物，别只按本实例视角判断。

释放实例前先将保留产物同步到文件存储或下载本地，并核实转存结果。不要把临时产物长期堆在按量计费的文件存储。

```bash
ssh <别名> 'df -h / /root/autodl-tmp /root/autodl-fs'
$CLI instance set I01 --disk "sys:12/30,data:40/50,fs:5/200" --brief
```

用量单位 GB。--disk 逐盘合并，没提到的盘不动；`data:none` 清空该盘。用量达到 90% 时 show 的盘行带 `!`，check/show --brief 有提醒；先核实、清理或扩容再开任务。满盘处置见 [协议](protocol.md#磁盘处置)。

## TensorBoard

事件文件写数据盘，用软链接入内置读取目录，不要写满系统盘：

```bash
TB=/root/autodl-tmp/tf-logs/<项目名>
mkdir -p "$TB" /root/tf-logs
ln -sfn "$TB" /root/tf-logs/<项目名>
# 每个任务独立 run，例如 "$TB/F01-T02"
tensorboard --logdir "$TB"  # 确需独立服务时，由调用方管理后台进程
```

换 logdir 前先定位并核实本项目 TensorBoard 进程，按授权停止后重启；不要批量杀掉所有 TensorBoard。自定义服务可用 `--port 6007` 从 AutoPanel 进入；需要公网直链时使用 `--port 6006 --host 0.0.0.0`（平台映射 6006/6008），确认用户允许对外访问。计划不记录 TensorBoard 路径/链接，保存在远端脚本中。

## 余额与定时结算

**Token 只在面板上填，并且只存在面板进程的内存里**：打开面板 → 点表头的「Token」→ 粘贴控制台 → 设置 → 开发者Token。没有第二个来源——不读环境变量、不读任何文件，CLI 也没有 `--token`。面板进程一退（重启、换端口重开都算）凭据就没了，要重新填。它只用于只读余额查询：Token 只进请求头，不写进计划、日志、异常文本或任何文件。

结算由面板进程负责：起面板时带 `--interval 30`，就每 30 分钟刷新余额并重算「还剩多少 GPU 小时 / 多少钱 / 够不够」；登记 Token 的那一刻也会立刻结算一轮，填错了当场就能在弹窗里看到接口怎么拒绝。**余额与凭据都不归 agent 管**：不必去找凭据文件、不必为结算另起常驻进程、也不必向用户索要 Token，缺凭据时结算只是少给结论。

```bash
$CLI instance set I01 --mode no-gpu --brief           # 无卡准备/持续请求等待；有卡开机用 --mode gpu
$CLI wallet set --assets 128.50 --voucher 20 --brief  # 面板没开或要人工核对时登记，汇报须注明
```

- 余额与代金券分别保存；可用时长只按现金算。缺时价、耗时或余额时少给对应结论，不补零、不猜数。官方余额接口使用千分之一元整数，换算由 CLI 完成，agent 不重复计算。
- 结算结论不超过 2 个周期时使用该快照；结算后计划变化会标明 changed，而不是悄悄当作新计划。超过 2 个周期回退实时值并注明过期。不要同时汇报快照与实时两套计划费用。
- 联网失败只写 last_error、保留上一份结论，不打断结算；面板进程下一轮自己重试，凭据填错或过期就在面板上重新登记。余额不足时提醒用户充值或调整计划，不擅自停训练。恢复细节见 [协议](protocol.md#结算恢复)。
- 面板不开就不结算（这是唯一的方式）：需要刷新余额时确认面板的后台任务还在跑（shell 的 `&` 或前台起的面板会随那次 shell 调用消失，见下节）。不要在仓库演示项目上启动 `serve --interval`，否则会改写版本库快照；真实实验用自己的项目目录。

## 面板

收到实验任务后随即起，作为用户在浏览器里看进度与实际花费的界面；`serve --port 8765 --interval 30` 本机监听 http://127.0.0.1:8765，把地址报给用户。**它必须以后台常驻任务运行**：用 harness 自己的后台任务机制起，既不要占着前台，也不要用 shell 的 `&`——面板是那次 shell 调用的子进程，父 shell 一退（命令跑完收尾、会话切换都算）进程就被带走，结算跟着停，用户页面直接失联。CLI 自己不后台化、不写 PID 文件、不注册系统服务（不碰 systemd）：常驻与日志都归起它的调用方。后台任务活在 harness 进程里，harness 一退面板就没了——重开前先确认旧面板没有在跑（端口被占说明面板已在跑，别重复起），重开后 Token 要重新登记。页面展示甘特图、预算与结算，不展示磁盘条或 TensorBoard 链接。

面板上能改的只有两处，其余写请求一律拒绝：**时价**——点实例卡右上角按钮登记/清空当前档位的费率（无卡按 `--mode no-gpu` 登记无卡费率，有卡按 GPU 时价），它是标价，不构成一次对机器的观测；**Token**——表头按钮，只进面板进程内存，见上一节。
