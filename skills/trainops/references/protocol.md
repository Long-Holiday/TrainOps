# 异常与恢复协议

仅资源冲突、训练/准备故障、失败重跑、会话恢复、关机/交接或结算故障时读取。正常操作见 [入口](../SKILL.md)，参数见 [CLI](cli.md)，初次配置见 [AutoDL](autodl.md)。

## 状态与依赖

| 状态 | 含义 | 允许转换 |
|---|---|---|
| pending | 待执行 | running / blocked / cancelled（set --status done 自动完成启动与收尾，仍须核实产物） |
| running | 执行中，独占 GPU | done / failed / blocked / cancelled |
| blocked | 人工确认阻塞 | pending / running / cancelled |
| done | 进程已退出且产物核实 | 重跑先回退 pending |
| failed / cancelled | 失败/取消，不满足下游依赖 | 重试先改 pending |

同一 GPU 同时只允许一个 running，local 可并行；依赖未完成不能启动。运行中改实例/依赖/最早开始限制前，先核实远程进程已停止，再转为 blocked 或结束。计划不记录命令、commit、日志路径。

未巡检依据 checked_at：未记录或距最近巡检超过 1 小时即标记；--progress 会自动记录巡检，没有可靠百分比则只用 --checked。progress_at 是 ETA 的进度采样时刻，单独巡检不应伪造新进度。已超期或进度 100% 的运行任务完成时间回退待估，先核实进程/产物，不直接当作 done。

## 恢复与关机

代码同步、MCP `trainpilot` 即时通知以及完成/取消后的调度清理和最终汇报，统一按[执行与通知闭环](execution.md)执行；关机不是收尾的全部，任务面板可以保留。

1. 新会话先 show --brief；恢复实验 Run 与待补录项见[实验日志](experiments.md)，不要重建表或把恢复巡检当新 attempt；有省略或异常时按需 show/check，再 SSH 核实远端会话、进程、checkpoint，禁止盲目重启或覆盖账本。
2. 远程执行训练/准备脚本先 source /etc/network_turbo，训练放 tmux/screen。摘要里的“依赖就绪”只是计划候选，不保证实例在线或已分配 GPU；无卡准备与有卡训练的切换见 [开机模式](autodl.md#无卡准备与训练开机)。恢复时用 `instance_status(instance_uuid)` 核实当前模式，用 `job_status(job_id)` 即时核实已有开机/切换任务，仍活动且需等待时优先 `wait_for_job(job_id, timeout_seconds=15)`（时长不超过授权剩余时间与调用超时上限）；缺货默认立即返回，汇报 `phase`、`elapsed_seconds`、`attempts`、`suggested_next_poll_seconds`；要等这台机器时按建议秒数用宿主定时调度器挂起（Antigravity CLI 为 `schedule`），到点再 `job_status` 复核；宿主没有定时能力时才显式 `return_on_capacity=False`，不紧密重复默认调用；等待超时或取消等待不取消后台任务，按返回 `phase` 处置；任务仅存于 MCP 进程，服务重启后丢失不代表实例已关机，不盲目重发请求。
3. 最终关机前确认进程退出、结果保存，检查所有流程无后续复用该实例且获用户授权，再通过已有 `autodl_mcp` 工具执行（故障止付与“取消任务并关机”按各自已有授权执行，见下节）。无卡准备完成后为切换 GPU 模式而中间关机，不受“无后续复用”限制，但仍须准备进程退出、配置/产物落盘并获授权；已运行实例优先 `switch_mode(instance_uuid, target_mode="gpu")`，由一个后台任务确认关机再开机；反向用 `target_mode="non_gpu"`，同样须确认中断与计费影响已获授权。切换不是可回滚事务，失败后先查真实状态；活动期间不另提交同实例开机或切换。工具不支持时才分步 `power_off`，用 `instance_status` 确认关机完成再 `power_on`（缺货自动持续重试），保留后续训练为待执行。`cancel_job` 仅停止后续尝试，不撤销已接受开机、不自动关机，但会返回取消后即时 `resulting_status` 与 `resulting_start_mode`：稳定态可直接判读，过渡态或查询失败（`resulting_status_error`）再查 `instance_status`；止付用 `power_off`，它会先取消活动切换，防止后续自动拉起，不能用切成无卡代替关机。TrainOps 本身不下发开关机指令。
   等依赖或后续任务尚未就绪时，可按已有授权保全后中间关机并保留后续计划；“所有流程无后续复用”只约束最终收尾，不要求 GPU 一直开到最后。没有关机授权时及时说明空闲计费并请求决策，不关闭仍有其他任务运行的实例；细则见[按需用卡](autodl.md#按需用卡与空闲处置)。
4. CLI 拒绝把仍有 running 的实例标为 off/unreachable；先核实远端并更新任务状态，不为绕过校验随意改状态。释放实例前还须转存并核实数据盘产物。

## 故障自愈与止付关机

TrainPilot 告警按钮按[通知与决定](trainpilot.md#异常与直接对话)处理。自行解决时执行、验证并用一次 ACK 汇报；选择等待用户后保持现场，停止循环轮询，等用户直接对话给出方案，不从飞书拉取信息。取消任务并关机须实际停止、保全产物并核实关机后回执。五次上限与既有止付授权不变。

训练或准备出问题（进程崩溃、OOM、依赖/数据缺失、SSH 断、盘满、GPU 不可用、checkpoint 损坏）时，先如实报告再动手，最多自愈 5 次；5 次后仍无法继续就先关机止付，再报告等决策。目的是别让实例一边报错一边按小时计费。

1. **先报告**：单行写清现象与已核实的证据（进程是否在跑、日志关键行、`nvidia-smi`、盘用量、`instance_status`），并说明影响哪个任务。不静默重试、不伪造进度、不把任务提前标 done。
2. **有依据地自愈**：先定位原因再改，按原因对症处理——调参数/降 batch、补依赖、清盘、重下数据、重启训练进程；运行时改实例/依赖/开始限制仍按 [状态与依赖](#状态与依赖) 处置。科学对照保持变量控制；工程修复可按根因成组修改，每次尝试后核实真实结果（进程在跑、GPU 在用、checkpoint 在写），避免无新证据的重复，瞬时故障可合理退避重试。**5 次是上限不是配额**：修好就继续训练，不必凑满。
3. **第 5 次仍无法继续 → 先关机止付**：先结束训练/准备进程（在 tmux/screen 里确认已退出）、确认必要产物与日志已落盘，调用 `power_off(instance_uuid)`，再用 `instance_status` 确认真已关机（`accepted=true` / `shutting_down` 都不够）。任务按真实结果记 `failed`（若在等用户拍板则记 `blocked`）并附单行备注，不标 done、不留 running，也不为绕过校验改实例状态。这是止住空转计费的**中间关机**，属用户对“5 次自愈失败”的预授权：不必再等一轮确认，保留实例与后续任务，不受“无后续复用”限制。
4. **关机后报告并等决策**：说清现象、试过哪些修复、凭什么判断无法继续、已发生的费用与产物状态，并给可选方案（换实例、改配置、缩范围、放弃）。重新开机走原来的授权与 [开机流程](autodl.md#无卡准备与训练开机)，先核实实例真实状态与产物，任务回退 `pending` 重跑，不盲目重发请求。
5. **不必凑满 5 次**：已明确无法继续的——平台侧故障（实例不健康、长时间缺货、网络不可用）、或需要用户拍板的变更（数据缺失、验收口径变化、要加钱）——可直接止付关机并说明理由。5 次上限约束的是“还能靠自愈推进”的情形，不是让 agent 硬试五次再关机。

关机按已有任务授权执行，覆盖的操作不重复请示；TrainPilot 的“取消任务并关机”按钮也授权对应任务专属实例的取消关机。缺少授权或存在其他任务冲突时请求决策。释放实例和超出约定的持续请求等待不能沿用故障止付授权。

## 磁盘处置

SSH 用 df -h 检查三盘，必要时只查看相关目录占用，登记方法见 [配置](autodl.md#三盘与用量)。用量达到 90% 时需处理；清理前核实目标，不删除唯一 checkpoint 或其他实验产物。文件存储是所有实例共享的同一份，删它上面的东西前先确认不是别的实例正在读写的产物。

| 满盘位置 | 处置方向 |
|---|---|
| 系统盘 | 核实缓存占用，将数据/checkpoint 移至数据盘；避免清理破坏训练环境 |
| 数据盘 | 先转存必要产物，按保留策略清理中间权重或扩容；扩容涉及费用先确认 |
| 文件存储 | 共享盘：先确认目录归属与是否仍在被别的实例使用，再检查长期产物与小文件/inode；用量计费，不要当临时盘 |

## 结算恢复

- Token 只从面板登记、只存在面板进程内存里，口径见 [配置](autodl.md#余额与定时结算)。没有 Token 不算故障：仍用已有余额结算并标明未配置。
- 网络/API 失败：last_error 保存单行原因，保留上一份结论，不打断循环；check/show --brief 报提醒，面板进程下一轮自己重试。凭据填错或过期时，请在面板上重新登记（面板重启后也要重填）。
- 结算面板不开就不跑：需要刷新余额时确认面板的后台任务还在（`serve --interval`；用 shell 的 `&` 或前台起的面板会随那次 shell 调用消失，见 [面板](autodl.md#面板)）。人工顶替用 wallet set --assets/--voucher，汇报注明人工登记；无参数会被拒绝。
- 新鲜结算若标记“结算后计划有变更”，不能当作新计划费用；超过 2 周期会退回实时值。缺字段是数据不足，不是零花费或余额足够。
- schema 版本不符或文件损坏时先备份并核对文件，开发阶段没有自动迁移。允许按[直接编辑规范](cli.md#直接编辑计划文件)修复已确认的问题，保留计划、配置和 Run 历史，运行 check --strict 校验；不确定时保留备份并说明阻塞，不用 demo --force 覆盖真实计划。

## 实验日志故障

飞书授权、字段、网络或限流失败只影响同步；先本地留痕，下次巡检用 `experiment sync` 补录，不纳入训练五次自愈，也不延迟关机止付。建表结果不确定时禁止盲目重建，先在飞书核实再用 `experiment init --url` 绑定。详见[实验日志](experiments.md)。
