# 多实例训练操作协议

## 1. 工作范围与授权

TrainOps 为任何能读文件、执行本地命令的 agent 附加训练管理规范。它不授予新权限，不要求调用模型 API，不接管 agent 原有身份。不同工具采用各自的能力加载和审批机制；提示词不能绕过这些边界。

用户需要明确：实验目标/协议、项目目录、每台 AutoDL 实例 ID 与 SSH 别名映射，以及本次可以执行的实例/仓库/通知操作。已有上下文中的明确映射可复用，不反复询问；缺失或冲突的映射先澄清，不猜测其他实例。多实例不意味着所有实例都要开机，只启动已分配可执行工作的资源。

- 不自行降低训练轮次、缩小数据、换模型、删实验组或修改评估协议。
- 提交、推送、开关机、取消进程、向外部目的地发送结果，遵循用户当次授权及宿主工具权限。角色文档本身不是授权。
- 不把 SSH 密码、MCP token、私钥或完整带密钥命令写入计划。计划与页面包含路径和命令，仍应视为私有工作数据。
- 本地 CLI 不对接 MCP、不连 SSH、不执行计划中的命令、不代替调度器。操作后的计划状态应反映事实，不能因为 CLI 成功就宣称远程成功。

## 2. 计划、依赖与分工

项目使用 `.trainops/plan.json`，同机 agent 共享同一绝对路径。文件锁只保护本机文件系统上的协作；不要把网络盘锁或不同机器上的复制文件当作可靠协调。计划不得由 agent 整体覆盖，所有更新走 CLI。

层级：项目 → 流程 `F01` → 节点 `F01-T01`；实例 `I01` 独立登记。编号是用户对话和协作中的稳定引用，名称/状态/实例变化不改变编号，取消也保留记录。流程之间默认并行；节点之间**只有明确依赖才要求先后**。同实例默认独占串行，顺序估算按依赖就绪时间及编号；想指定先后就添加依赖。本地节点用 `local`，可并行，不占 GPU。

每个需要独立交接的步骤建节点，例如准备数据、训练、评估、汇总。每个节点填入预期产物和必要依赖；消费者使用生产者已核实的产物路径、版本和配置，而非“服务器上最新文件”。不要把每个 shell 命令拆成任务，也不要把整次多阶段实验藏进一个节点。

执行次序：
1. 读取最新计划及 `estimate.ready`，确认授权与依赖实际产物。
2. 使用当前会话唯一 owner 将节点原子变为 running。独占冲突/依赖错误必须处理，不规避。
3. 核实远程真实进程和 GPU 是否有计划外工作。有其他训练时停止启动，记录冲突，不杀进程抢资源。
4. 执行准备与训练。running 表示该节点已认领、正在准备/执行，不等于已经观测到远程训练；`started_at` 是节点执行开始，实际训练命令/会话在启动成功后记录。
5. 记录每次实际观测，阶段结束先验证产物，再 done。继续下一个节点前重新读取计划。

owner 是协作约定，不是认证系统。多个 agent 不能用同一个 owner，并且不能只凭 owner 字符串接管工作。若需要跨实例/换 owner，先核实原进程已停止、原 agent 不再操作，再将节点标为 blocked，更新分配，再由新会话启动；不要把仍执行的任务改成 blocked 释放本地锁。

### 状态约定

| 状态 | 含义 | 后续操作 |
|---|---|---|
| pending | 尚未执行，可派发性由依赖/时间/实例决定 | running / blocked / cancelled |
| running | 已认领，准备或执行中，仍占用该实例 | done / failed / blocked / cancelled |
| blocked | 人工确认阻塞；没有仍在执行的远程进程 | pending / running / cancelled |
| done | 进程结束，产物已核实 | 要重跑先 pending；若下游已执行，先处理下游影响 |
| failed | 本节点失败且执行已停止 | 保留诊断，再 pending 重试或 cancelled |
| cancelled | 用户取消且执行已停止；不是“依赖已满足” | 明确恢复时 pending |

运行中日志异常但进程还活着：保持 running，note 写异常并立即汇报。不要只为好看改 failed/blocked。重试回 pending 会清空 owner、进度和实际起止时间；旧命令、日志、备注等保留作线索，重启前重新核实并更新当前证据，必要时在 note 保留上次失败和检查点。

CLI 校验只是本地一致性保护，不能证明进程退出或产物存在；这些由 agent 观察。取消依赖不会自动取消下游，失败也不自动迁移实例或重试。

## 3. 开机、SSH 和代码同步

- 用可用的 MCP autodl 操作用户明确指定的实例。开机无空闲资源时，用真实排队/重试能力，采用有间隔的重试，直到用户取消、授权期限结束或成功；登记等待状态/调度 ID，不 busy loop，不把一次失败当作最终完成。
- 开机成功后检查实际实例身份及 SSH 目标，连接信息变化时核对映射。CLI 会拒绝运行任务期间更换实例 ID/SSH 别名：先协调暂停、核实原进程，再更新，不能静默重定向。
- 每次远程 Bash 工作先在**远程**执行 `source /etc/network_turbo`，再进行远程准备/训练。它不是本机初始化命令。文件缺失或初始化失败时报告并确认是否允许替代，不能以 `|| true` 掩盖失败。
- 本地修改受版本管理代码并验证，记录仓库/分支/提交。需要 git 同步时，在授权范围内提交相关变更并推送，服务器先核对工作区，再拉取或检出**指定提交**；不同实例使用各自明确的 commit，不无条件拉“最新”。
- 不在服务器直接改受版本管理代码，不覆盖用户未提交内容，不强制推送，不夹带无关变更。使用用户授权的非 git 同步方式时，记录确切版本/校验信息。
- 使用 tmux、screen 或可靠的后台进程管理器，使 SSH 断开不影响训练。以任务编号命名远程会话、日志和输出目录；启动前检查同名会话/进程，避免重复启动。
- 保存实际启动命令、提交 SHA、进程/会话标识、日志和产物路径。只查会话是否存在不够：检查目标进程、退出码/结束标记及最近日志，避免“tmux 活着 = 训练成功”。

## 4. 预计完成时间

CLI 在每次读取时派生 ETA，不写回实际字段。根据预计总耗时、节点实际开始、带采样时间的进度、not_before、依赖和实例串行队列估算。进度推算假设速度近似稳定，数据加载/评估/保存成本可能使估计失准；最近观测过期时要重新巡检。

- 未知耗时不当作零；未知依赖结束会传给下游，同实例已有执行中/排队任务的未知耗时也会使后续队列待估。
- 失败、取消或显式阻塞的节点不产生可用于下游的完成预测。
- 运行超时显示“需重估”；进度 100% 仍待验证进程/产物，不自动 done。
- `estimate.ready` 仅表示已完成依赖、允许开始时间及本地已登记占用满足要求，不证明实例已开机、远程空闲或用户已经授权。
- 实例开机等待、网络/数据传输等应作为节点或计入耗时；没有记录的成本不在 ETA 内。
- 表格中的预测队列不是调度器；到预计开始时间不会自动执行。预计时间变化时解释依据，不给无依据的精确承诺。

## 5. 定时巡检与通知

优先使用宿主 agent 的真实调度工具。默认约每 30 分钟，用户指定整点/半点则按其要求。并行流程尽量共用一个项目巡检任务，按实例/节点归并结果，避免多个 agent 对同一任务重复调度和重复通知。负责执行的会话承担巡检，协调者负责汇总和调度记录。

必须验证调度已经创建、何时过期、会话退出后是否继续，以及任务是否有执行所需工具/项目路径/owner。将真实 ID 和限制用 CLI `monitor` 登记；多个调度 ID 可逗号分隔，note 写清对应节点。没有真实调度能力就明确说明，不能以“我会持续监控”代替实现。调度会自动过期的工具应说明期限，续期前核对旧调度，防止重复。

巡检核实：
- 实例状态、目标训练进程/会话及 GPU 使用；有无计划外任务。
- 日志最后更新时间、是否有持续输出；不要因一次短暂静默断言死锁。
- 当前 step/epoch/进度、可获取的 loss/评估指标、来源/采样时间。
- 存储空间、关键错误、检查点及产物；无法获取的字段明确标注未观测。
- 下一步动作、依赖等待、更新后的预计时间。

实际检查后用 task set 的 `--checked --owner ...` 登记，实例检查用 instance set 的 `--observed`。只改备注或打开 Web 页面不算巡检。重大节点（开机、同步、启动、阶段/评估完成、故障、恢复、收尾）立即额外汇报。

有可用 MCP trainpilot 且用户确认目的地/内容范围时使用；缺少时向当前会话汇报，若要求外部通知则作为独立阻塞。报告带任务编号、实例、真实观测、产物和下一步，不编造缺失指标。

## 6. 收尾、取消和停用

按实例判断，不按单流程判断。正常关机前：
1. 本节点进程退出、结果和检查点可用，状态已落盘。
2. 检查本项目跨流程待执行节点，是否还要使用该实例；即将开始的任务不必反复开关机，长间隔如何处理按用户资源策略。
3. 核实远程没有其他项目/用户的工作。本项目计划“没有 running”并不能证明服务器空闲。
4. 确认用户关机授权，执行后实际检查实例状态，再登记 off/observed。

失败先保留日志尾部、退出状态、版本、检查点和复现线索，及时报告，按用户要求恢复或结束；不要在诊断尚未保存时关机。取消前确认范围，按授权停止目标进程，不误杀整个服务器的 Python 进程。确认停止后才将节点 cancelled，报告受影响依赖。

项目结束清理本次创建的巡检、开机等待和本地页面服务，不能删除其他会话的任务。部分流程结束仍有并行任务时，不清理共用巡检。调度删除成功后更新 monitor，注明已停止；不只清空记录而让真实任务继续执行。

停用能力仅停止新增管理动作：保存计划、列出仍运行节点、实例、巡检与 owner，明确谁接管。未经用户授权不停止训练/关机。若没有接管者，说明费用和无人巡检风险，待用户决定。后续启用继续用原计划，并重新核实远程事实。
