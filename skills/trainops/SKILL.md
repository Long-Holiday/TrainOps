# TrainOps

保留原角色。仅加载能力时不建表、不启动进程；收到实验任务后，以**缩短假设到有效结果的时间**为目标，在验收、预算和资源授权内自主推进。设 `CLI="python3 <本目录>/scripts/trainops.py -p <实验项目目录>"`。

## 开工与接管

先 `show --brief` 并核实已有任务、实例和远端进程，不覆盖已有计划或重复启动。明确目标、必需实验、评测协议及授权范围；已经授权的操作不重复请示。可自主重排、拆并任务、改派合格实例、复用产物和修复工程故障；改变目标、放弃指定实验、改变评测协议或超出费用授权时再请求决策。

尽早以 harness 的**后台常驻任务**起 `$CLI serve --port 8765 --interval 30`（别用 `&` 或前台），报出地址；先核实旧面板项目，端口冲突换端口，不杀其他面板。面板同时结算，不另起 monitor。主动执行 `experiment init` 复用已有/指定表，未指定则自动创建实验日志；飞书失败不阻断本地记录、训练或止付。初始化和独立准备可并行，不把外部同步当成训练前置依赖。

启动新训练前必须实际执行一次 TrainPilot 探针并判读返回，按 [调用与开工探针](references/trainpilot.md#调用与开工探针)执行；探针未通过先解决通知阻塞或取得用户明确同意的替代方案，再启动训练。接管已有训练先核实现状，不因探针失败中断进程；安全处置和关机止付继续执行。

需要远端准备时默认 `power_on_no_gpu`，资源仅 0.5 核 CPU、2GB 内存、无 GPU，适合轻量检查和配置；重型编译/数据处理留给资源充足的授权环境。已核实无需准备或已有训练时直接复用。准备就绪按授权 `switch_mode` 转有卡，检查真实 GPU 与训练入口后启动；SSH 可达和开机请求已提交均不代表 GPU 就绪。工具契约按需读 [AutoDL](references/autodl.md)。

## 计划与流程图

推荐 `$CLI apply --from-json - --brief`：无计划时创建，已有计划时增量修改；`--dry-run` 预览。用 `instances/flows/tasks/updates` 具名字段及本次请求内 `key` 引用，读取回执 `aliases`，后续用真实编号；未知耗时填 null，`deps: []` 表示无真实依赖。JSON 不自动串联，执行队列顺序不写成 deps。单项用 `set`，已有 `init` / `batch` 继续可用。见 [CLI](references/cli.md)。

也允许 agent 直接编辑 `.agent/experiment.yaml`，适合整体整理或 CLI 无法表达的调整。先读最新文档并备份，保留 config、experiments、编号和无关字段；避免与面板结算或其他写入并发，修改后运行 `check --strict`，校验通过后再启动受影响任务。文件是 JSON 兼容 YAML，不能换成解析器不支持的缩进式 YAML。CLI 提供锁、原子提交和自动编号，通常更省事；直接编辑的具体要求见 [直接编辑](references/cli.md#直接编辑计划文件)。

面板是账本的视图，候选队列和预计时间不是远端执行证据。同一实例默认一个 running，local 可并行；保留真实依赖，不用 running 占位。单 agent 在任务完成/失败、实例可用和巡检时查看全局待执行任务，重新核实分配和原远端队列后实际启动，避免旧队列重复执行；不只改面板。见 [多机再平衡](references/cli.md#单-agent-多机再平衡)。

## 实验执行与决策

训练通过 SSH 在 tmux/screen 等断线后可继续的会话中运行，保留实际命令、版本、日志、产物和进程引用。代码本地修改验证、按授权提交推送并远端拉取核对，不覆盖用户工作。见 [执行与通知闭环](references/execution.md)。

实验日志先读后写：新尝试/接管时 `experiment show` 看当前及最近相关 Run，不必全量；连续操作已经读过且未变化的记录可直接增量更新。核实实际启动后 `experiment start`，巡检/结束用 `experiment update`，恢复沿用活动 Run，真正重跑新建 Run；`experiment sync` 补录失败同步。记录意图、改动、基线、真实指标（含 extra_metrics）、协议和证据。每轮结果后比较可比基线，判断假设是否成立及下一轮最有价值的工作；缺测不补零，不把训练 loss 当最终评测。见 [实验日志](references/experiments.md)。

故障先上报证据，按 TrainPilot 当前协议处理按钮决定；常规修复在已有授权内推进。修复按根因选择，可成组调整相关工程配置，科学对照实验保留变量控制。避免没有新证据的重复，瞬时故障可退避重试。最多 5 次仍无法继续即先关机止付（已有预授权），保全产物并记 failed/blocked，再报告等待决策；不必凑满次数。用户选择等待时保持现场等待直接对话，不从飞书消息中拉取方案。取消任务并关机须停止本任务、保全产物、取消其开机重试并核实关机；不影响其他任务。见 [恢复协议](references/protocol.md)及 [TrainPilot](references/trainpilot.md)。

## 唤醒与汇报

训练启动后实际登记整点半点汇报：`schedule(CronExpression="0,30 * * * *", Prompt="[强制动作] 1. SSH 与 AutoDL 检查实例、训练进程、GPU 和日志，取得真实进度与指标；2. 调用 trainops 更新计划进度及真实 Run，写表失败也继续下一步；3. 必须实际调用 call_mcp_tool(ServerName='trainpilot', ToolName='report', Arguments=真实任务事件) 推送巡检卡片并核实返回，终态直接 completed/failed，修复结果以一次 ack_instruction 代替重复 report；4. 对话总结状态、结果、方向与费用，推进下一任务。逐任务使用已绑定的 task_id；写表成功或文本回复不能替代第 3 步", IsDaemon=false)`，用户另定周期则遵从。执行检查与汇报分开：按预计结束、故障和缺卡退避安排更早的一次性唤醒，完成后及时接续，不等下一次半小时通报。调度仅在宿主支持的生命周期内有效，记录标识以供接管/清理，不声称跨退出持续监控。

重大结果及时通知；修复结果只汇报一次，不为同一修复重复 ACK 卡和 milestone。最终报告包括有效结果、产物位置、下一步、费用已知范围与实例状态。MCP `trainpilot` 用于即时通知与按钮决定，lark-cli 用于实验历史，两者互不替代；不接收飞书下一步计划，新增任务由用户直接对话交办。完成/取消清理本任务不再需要的唤醒和资源等待，面板可保留。

Token 和时价仍从面板输入；Token 只存面板进程内存。未知进度/耗时/价格/余额保留未知，观测值与估计分开。共享存储分任务目录，关机前核实产物，释放实例前转存数据盘内容。
