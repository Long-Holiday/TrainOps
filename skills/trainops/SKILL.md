# TrainOps

保留原有角色，仅在交办训练或计划任务时操作。设 `CLI="python3 <本目录>/scripts/trainops.py -p <实验项目目录>"`（`-p` 指实验项目，不是本仓库）。**"不建表、不启动进程"只约束加载阶段**：没有具体实验任务时不建表、不起面板；**收到任务后按开工顺序执行**——起面板、无卡准备、再按授权申请有卡训练。

## 开工顺序

1. **计划**：`show --brief`；无计划时按目标、验收与授权范围建表（见 [CLI](references/cli.md)），耗时、依赖不定就留待估；已有计划先核实、不覆盖。
2. **面板**：随即起 `$CLI serve --port 8765 --interval 30`（放后台、顺带结算），报出地址 http://127.0.0.1:8765 。端口占用说明面板已在跑。
3. **无卡准备**：默认先 `power_on_no_gpu` 了解项目、配环境、改代码，就绪关机再申请有卡；除非用户要求持续请求或已核实无需准备，才直接 `power_on`。**不交付空等 GPU**，中间关机属准备流程；不支持无卡时说明限制。
4. **训练**：核实 GPU 后启动，登记真实进度。

## 自主调度

以用户目标、验收标准和明确硬约束为准，任务清单与顺序不是僵硬脚本。按真实依赖、资源、成本、耗时与实验结果自主优化调度：重排、拆并任务、调整实例分配，先验证高风险环节，避免 GPU 空等与重复实验。合理调整不必逐项请示，用 CLI 同步计划并简述原因。

不为提速绕过依赖或降低验收。冗余、失效或低收益任务可提替代方案；改变目标、放弃用户要求的实验、增加未授权费用或中断任务，先确认。见 [调度决策](references/cli.md#调度决策)。

## 安全边界

- `$PROJECT/.trainops/plan.json` 是唯一事实来源，只经 CLI 与面板时价修改：禁止直接 Edit/Write JSON、不覆盖已有计划；恢复先核实，不盲目重启。
- 编号固定：实例 `I01`、流程 `F01`、任务 `F01-T01`。只记任务名、实例、耗时、依赖、状态与进度，命令、日志、commit 留远端。
- 同一 GPU 只跑一个任务，`local` 可并行；依赖未完成不得启动。done 前核实进程退出与产物；关机须用户授权，最终关机须无后续复用（开工顺序 3 除外）。
- 代码/环境放系统盘，数据/checkpoint/TensorBoard 放 `/root/autodl-tmp`，长期产物放 `/root/autodl-fs`（文件存储对所有实例共享，跨实例交接走它，各自分目录别撞名）；数据盘不随镜像保存，释放即丢，释放前先转存。
- 缺进度、耗时、费率或余额就保留待估，不猜数字、不补 0；可用时长只算现金、代金券另列；开机模式用 `--mode` 记，费率与 Token 在面板登记。

## 日常闭环

- 状态流转：`show --brief` → `set <任务> --status running` → `--progress 40`（真实观测）或 `--checked` → `done`，均带 `--brief`
- 建表/结构调整见 [CLI](references/cli.md)：`--brief` 结构编辑附检查，问题须修、提醒须判读，不撤销编辑；纯状态更新后不必再跑 check + show。
- 每 30 分钟 SSH 巡检（用户另定则遵从）；`--checked` 只记巡检时间、超 1 小时未记即未巡检；摘要限量并注明省略数，按需 show/check 看全量。
- 配置见 [AutoDL](references/autodl.md)，异常见 [协议](references/protocol.md)，按需再读。结算由面板进程负责（余额与凭据都不归你管），别另起常驻结算进程；正常简报，完成/失败或需决策时说明。
